I tested zero-shot, explicit output constraints, few-shot examples and a step-by-step extraction procedure across sentiment classification, product description generation and data extraction using independent baseline batches of 5, 10 and 15 runs, followed by version comparisons and task variations. All v1 baseline responses failed the strict output contract, although the displayed sentiment and extraction responses often conveyed the intended meaning; explicit v2 constraints produced 15/15 base-case passes for both tasks, and v3 preserved those results. Product v3 appeared to pass 14/15 automatic checks, but manual review found only 1/15 responses compliant with both factual and style requirements because unsupported claims escaped the original screen. After adding explicit claim exclusions and neutral few-shot examples, the independent v3r1 final product batch passed 15/15 automatic and manual checks, with all revised product variations also passing. The clearest observed gains came from explicit output contracts and the evidence-driven product revision; few-shot and CoT effects were not isolated. Extraction still failed every corrected-date and embedded-instruction variation, showing that repeatable JSON can be consistently wrong. Next time I would strengthen date normalization and data/instruction separation, evaluate each technique separately on unseen cases, improve factual checking and assess product persuasiveness without sacrificing support for claims.
